Branch `worktree-wf_f1763a7e-b6c-3`, built on the foundation `941a0be`. Port 8104, database `ldm_w`.
The look follows `docs/ldm/briefs/design-direction.md` (the coordinator's correction during the

## What landed, by brief item

1. **Design tokens and formatting** — `static/src/scss/ldm_tokens.scss`: ink `#14213D` for structure
   and the one primary action, a `#EEF1F5` desk under white paper, stamp violet `#5B3A9E` used only
   for what is officially confirmed (the "Approved" stamp on a matter, "Confirmed genuine" on a
   document), and the four meanings (red overdue or rejected, amber due within 48 hours or missing,
   green done or received, blue waiting on someone else). Radii by hierarchy (bands 0, panels 10px,
   inputs 6px, pills round), a 4px kind spine on every matter row, type sizes 13/15/18/22/28, logical
   properties only, all scoped to `.o_ldm` (and the footer of a dialog that holds an `.o_ldm` form).
   Fonts: Noto Kufi Arabic for headings and matter numbers, IBM Plex Sans Arabic and IBM Plex Sans for
   text, vendored as woff2 under `static/lib/fonts/` with their OFL. Icons: a 64-icon Lucide subset
   (`static/lib/lucide/`, ISC) drawn by the `LdmIcon` component as CSS masks; no Font Awesome is left
   in `static/src`. Both are generated by `docs/ldm/tools/gen_ws_assets.py`. The stamp settles in
   180 ms and does not move under `prefers-reduced-motion`. `core/ldm_format.js` has the IQD formatter

   Ctrl K search, the approvals chip, scopes me / my team / everyone for managers, New matter.
   The 7-day agenda rail; the clerk's "today's visits, by body" with the documents to carry and the

   body's target when G ships `_ldm_past_target_domain`, conflicts waiting, judgments waiting for a

   only; every count opens exactly the records it counted. Keyboard: arrows, Enter, `/`,
   Alt+Shift+N. The auditor sees every row and no action.

4. **Cockpit** (`static/src/cockpit/`, js_class `ldm_matter_form`) — the ink title band (number,

## Not delivered, and why
- **Charts board and the dossier's service matrix** from design-direction.md: left for a follow-up
  round, as the coordinator's correction allowed.
- **Arabic strings**: every W string is English source, as the brief asks; the screens therefore
  show English labels beside Arabic data until integration produces the catalogue. Text that mixes
  the two keeps its own order (`dir="auto"` on free-text spans, `unicode-bidi: plaintext` on the
  hand-over summary), so nothing reads backwards meanwhile.
- **Matters list** (S4) still shows eight default columns: that list is the foundation's view.
- **Dark mode**: tokens have a dark set compiled into the dark bundle, but Community has no user
  dark mode, so it is untested on screen.

## Decisions
- **Hand-over with an end date is a cover**: the colleague joins the teams and takes the work dated
  up to that day; nobody is removed from a matter. Without a date it moves for good.
- **Counts only for managers and the auditor**: a lawyer's My Day is the list itself; a strip of
  zeros and totals above it only pushed the work down.
- **Names on approval rows read with sudo**: an approver outside the client's team must still see
  which client and body a request concerns (`matter_line`, `ldm_approval_preview`); only names are
  read that way, never the matter.
- **Waiting for approval is blue** (waiting on someone else); violet appears only when the approval
  is given, as the stamp.
- **A received document is green**, a verified one carries the "Confirmed genuine" stamp.
- **Fallback session calendar** in `ws_views.xml` at priority 90, so L's own calendar wins when it is
  installed.
- **IQD shows whole dinars** in W's components and `hide_trailing_zeros` in the inbox list.

## Requests to the foundation
1. Approvers cannot read the client (`legal.company`) of a matter waiting for their approval; W reads
   the names with sudo for now. A read rule for `group_ldm_approver` on the clients of matters in
   `to_approve` would let that go.
2. The matters list (`view_legal_task_tree`) has eight default columns; the budget is six.
3. M: a stable code for the government fee expense category (W looks for `government_fee`,
   `GOV_FEE`, `gov_fee`, `GOV`, then a name containing "government").
4. L: the hearing roll report `action_report_ldm_hearing_roll` (on `legal.hearing` records, or with
   `data={"date_from", "date_to"}`); "Print roll" stays hidden until it exists.
5. G: `legal.task._ldm_past_target_domain()`; the manager band stays empty until it exists.
6. M: `ldm_conflict_check` receives `[client name, opponent name]` from quick create, then again with
   `task_id` once the matter exists so the check is recorded against it.

## Interfaces other streams can call (all on W's own models, safe defaults)
- Quick create context: the usual `default_<field>` keys of the wizard (`default_template_id`,
  `default_legal_company_id`, `default_department_id`, `default_key_date`), and
  `ldm_quick_create_vals` (a dict merged into the values given to `create_from_template`). Override `legal.task.create.wizard._ldm_after_create(task)` to add work
  after creation (call `super()`).
- `legal.task.action_ldm_use_suggested_target()` sets the target date to the suggestion.
- `legal.task.ldm_row_payload()` returns the row a workspace list draws for a matter.
- `legal.task.step.action_ldm_toggle_done()` / `action_ldm_undo_done(expense_ids)`.
- `legal.task.ldm_attach_document(document_id, attachment_ids)`.

  `view_legal_task_kanban`, `view_legal_company_form` and redefines `menu_ldm_agenda`; it must load
